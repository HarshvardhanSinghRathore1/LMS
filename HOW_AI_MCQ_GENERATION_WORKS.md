# 🧠 How AI MCQ Generation Works in Capacity Connect

## 🌟 Overview: In Plain English

In a standard LMS, AI question generators often produce generic questions or "hallucinated gibberish" simply by looking at a course title. 

In **Capacity Connect**, the MCQ generator works like an **expert human trainer**:
1. It reads the **actual lesson materials** (lesson text, YouTube video transcripts, lesson notes, and uploaded PDF attachments).
2. It asks **Google Gemini** to formulate high-quality multiple choice questions based **strictly on that material**.
3. It passes every question through a **strict backend validation engine** that eliminates duplicates, invalid options, and hallucinated answers.
4. It places questions into a **Trainer Review Queue** so a human trainer can inspect, edit, 1-click regenerate, or approve them before they ever reach trainees.
5. Once approved, questions are imported into **Live Assessments** where trainees can take them, with answer keys protected on the server.

## 🚀 The 6 Key Steps Explained Step-by-Step

### 1. Multimodal Context Aggregation (`getComprehensiveLessonContext`)
When a trainer selects a Course, Module, or Lesson in the **AI Workspace** (`/ai-tools`), the backend searches database tables and pgvector chunks:
* **Lesson Text**: The main instructional body written by the instructor.
* **YouTube Transcript**: The verified spoken subtitles from the lesson video.
* **Lesson Notes**: Structured study notes generated or approved for the lesson.
* **PDF Resources**: Text extracted from attached PDF worksheets and textbooks.

> 💡 **Zero-Fabrication Guarantee**: If a lesson has no readable text or resources, the system stops immediately and returns a friendly notice: *"Insufficient source material available."* It will never invent facts from a lesson title alone.

---

### 2. Candidate Generation via Gemini (`AIProviderFactory`)
The backend packages the aggregated lesson material along with the trainer's settings (Topic, Number of Questions, Difficulty mode) and sends a prompt to Gemini requesting structured JSON:

```json
{
  "questions": [
    {
      "question": "What is the worst-case time complexity of binary search?",
      "options": ["O(1)", "O(log n)", "O(n)", "O(n²)"],
      "correctAnswer": "O(log n)",
      "explanation": "Binary search divides the search space in half each step.",
      "difficulty": "EASY",
      "questionCategory": "CONCEPTUAL",
      "sourceReference": "Lesson Notes"
    }
  ]
}
```

---

### 3. Strict Deterministic Anti-Gibberish Validator (`validateAndDeduplicateMcqs`)
Every single candidate question generated by AI must pass 6 deterministic checks:

| Rule | Requirement | Bad Example (Rejected) |
| :--- | :--- | :--- |
| **Option Count** | Exactly 4 options | 3 options or 5 options |
| **Uniqueness** | All 4 options must be distinct | `["Paris", "London", "Paris", "Rome"]` |
| **Answer Match** | Correct answer must match one option | `correctAnswer: "Berlin"` when options are A, B, C, D |
| **No Gibberish** | No meaningless placeholder strings | `"asdf"`, `"Option 1"`, `"N/A"`, `"xyz123"` |
| **Explanation** | Must include a educational explanation | Empty or missing explanation |
| **Topic Relevance** | Must be grounded in the lesson subject | Database question inside a Binary Search lesson |

---

### 4. Deduplication & Semantic Overlap Detection
* The system checks questions against each other using normalized text tokens (case-insensitive, punctuation-stripped).
* If two questions test the exact same concept (e.g. *"What is the time complexity of binary search?"* vs *"What is the Big-O complexity of binary search?"*), the duplicate is dropped.

---

### 5. Trainer Review & 1-Click Management (`/ai-tools`)
Generated questions are saved in the database with status `PENDING_REVIEW`. They are **never** published directly to students without human oversight.

In the **Trainer AI Tools** interface:
* **Preview Card**: Displays question category (`CONCEPTUAL`, `APPLICATION`, `SCENARIO`, `EDGE_CASE`), difficulty badge, choices, and source attribution.
* **[✨ Regenerate]**: Sends feedback to Gemini to generate a fresh replacement question while specifically excluding the old question.
* **[✏️ Edit]**: Opens an inline modal to modify question wording, swap options, or change the correct answer radio button.
* **[🗑️ Delete]**: Removes unwanted questions with one click.
* **[Approve & Import]**: Trainer selects which Assessment (e.g., *"Midterm Quiz"*) should receive the question.

---

### 6. Assessment Publishing & Trainee Attempt Scoring
1. **Atomic Import**: When approved, the question is copied into the `assessment_questions` table with point weights.
2. **Answer-Key Security**: When trainees open the quiz, the backend strips the `correct_answer` field so it cannot be inspected in browser developer tools.
3. **Authoritative Server Grading**: When the trainee submits their answers, the backend calculates the score percentage and records the attempt history.

---

## 🔒 Security & Multi-Tenant Boundaries

* **Tenant Isolation**: Every database query and vector retrieval filters by `organization_id`. Tenant A cannot access, regenerate, or import questions belonging to Tenant B.
* **Hidden API Keys**: Gemini API keys live exclusively in `.env` on the server and are never sent to the client browser.
